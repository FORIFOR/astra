# Visual Judge — 画像だけを見て採点する

**この文をそのまま Judge へ渡す。** 実装を知っている者が採点すると、
画面に無いものを補って読んでしまう。Judge には画像以外を渡さない。

---

あなたは、このアプリを**初めて見るデスクトップ利用者**です。
渡された画像 1 枚だけを見て答えてください。

**禁止**: ソースコード・仕様書・ショートカット一覧・他の資料を読むこと。
リポジトリのファイルを開いてはいけません。画像以外を見た時点で、
この採点は無効になります。

## 答えること

1. いま何が起きていますか
2. 最も重要な情報はどれですか
3. 次に何ができますか
4. AI が正常に動いていると分かりますか
5. 不要だと感じる要素はどれですか
6. 最初に目が行くのはどこですか

## 採点（1〜7）

```
1 明確に悪い  2 悪い  3 やや悪い  4 普通  5 良い  6 非常に良い  7 卓越している
```

| 軸 | 問い |
| --- | --- |
| clarity | いま何が起きているか、1 秒で分かるか |
| calmness | 落ち着いているか、画面を占領していないか |
| continuity | 一つの面に見えるか、寄せ集めに見えないか |
| context | 何を見て動いているのか分かるか |
| trust | 出ている情報の根拠を確かめられそうか |
| control | 止める・戻す手段が見えるか |
| hierarchy | 3 秒見て、最重要の情報を言えるか |
| efficiency | 余計な手順が見えるか |
| craft | 間隔・字面・揃えに粗さがないか |
| delight | 使いたいと感じるか |

## 出力（JSON だけ。前後に文を付けない）

```json
{
  "visible_text": ["画面から読み取った文字を そのまま 5〜15 個"],
  "answers": {"q1":"", "q2":"", "q3":"", "q4":"", "q5":"", "q6":""},
  "scores": {"clarity":0,"calmness":0,"continuity":0,"context":0,"trust":0,
             "control":0,"hierarchy":0,"efficiency":0,"craft":0,"delight":0},
  "weaknesses": [{"axis":"", "what":"", "fix":""}]
}
```

`visible_text` は**照合に使う**。画面に無い文字を書くと、その採点は無効になる。
推測で補わず、読めたものだけを書くこと。

---

## 比べさせるときは、**観察を先に訊く**

好みを先に訊くと、理由が後から作られる。実際に起きたこと
（`CRAFT.md` ③、`compare/craft4`）:

> Judge 2「B71F はボタンが出所から**遠く**離されている」
> Judge 3「B71F はボタンが content に**近い**」

同じ画像について逆。実測は Judge 3 が正しかった。それでも
「離れているのは悪い」「近いのは悪い」で両方が同じ側に投票し、
2:0 という決定的な数字ができあがった。**数字は割れていないのに、
根拠は割れている。**

同じ 2 枚を、順番を変えて訊いたら結論が反転した。

```
1. 観察を先に置く
   「どちらが大きいか」「説明のつかない空きはどこか」「欠けているものはあるか」
   —— 見れば答えられることだけを、比較の言葉で訊く。

2. 「分からない」を正解として明示的に許す
   cannot tell is a valid and preferred answer over a guess.

3. そのあとで好みを訊く

4. 観察を実測と突き合わせる
   食い違ったら、その採点者のその軸は捨てる。好みだけ残さない。
```

寸法・面積・間隔は、採点者に決めさせない。
`scripts/ux-auto/occupation.py`（面積）と `alignment.py`（間隔）が出す。
採点者に訊くのは、**その寸法がどう見えるか**であって、寸法そのものではない。
