# Astra Qualitative UX Scorecard

**採点するのは人。** アシスタントは点を付けない（自分で付けた点は根拠にならない）。
代わりに、各軸へ**機械で測れる事実**を添える。事実と評価を混ぜないため、
「実測」と「採点」は別の欄にする。

採点:

```
1 明確に悪い   2 悪い   3 やや悪い   4 普通
5 良い         6 非常に良い          7 卓越している
```

---

## 10 の軸

### 1. Immediate Clarity
**問い**: 初見で、いま Astra が Listening なのか Thinking なのか Executing なのか、
1 秒以内に分かりますか？

実測で添えるもの: 8 状態がそれぞれ別の絵であること（面どうしの総当たり比較）。

### 2. Calmness
**問い**: Astra はいまの作業を助けていますか、それとも画面を占領していますか？

実測: 焦点を奪った回数（0 が正）／idle の面積／面の空き。

### 3. Continuity
**問い**: Listening → Task → Meeting が、別の窓ではなく**続いた一つ**に見えますか？

実測: 全 Journey で増えた窓の数（0 が正）／上辺の Y が動かないこと。

### 4. Context Awareness
**問い**: Astra がいまどの画面・アプリ・選択範囲を見ているか分かりますか。
そしてそれを**やめさせられます**か？

実測: 文脈の出所が画面に出ているか（Sources の表示）。

### 5. Trust
**問い**: この Decision をなぜ Astra が作ったのか、**5 秒以内に**確かめられますか？

実測: 拾った項目のうち出所（いつ・誰が）が付いている割合。

### 6. Control
**問い**: 間違った操作を AI が始めたとき、**考えずに**止められますか？

実測: 走っている仕事に Stop があるか／外へ出る操作に確認があるか。

### 7. Information Hierarchy
**問い**: 3 秒見たあと、その画面で最も重要な情報を説明できますか？

実測: 面の空き（地の割合）／文字の行位置が揃っていること。

### 8. Efficiency
**問い**: 使うほど速くなりますか。覚えた人に余計な手順が増えていませんか？

実測: Journey ごとの操作数と所要時間。

### 9. Visual Craft
**問い**: 間隔・字面・動き・揃えに粗さがありませんか？

実測: 2pt の造形ゲート／行の隙間と端の揃い／AI っぽさの天井。

### 10. Delight
**問い**: 反応・動き・状態の変わり方が自然で、「使いたい」と感じますか？

実測: 状態遷移の所要時間（Dock の morph）。**ここは実測で代替できない。**

---

## 合格条件

```
平均            ≥ 6.0 / 7
各項目          5.5 未満が無い
Critical 4 項目 Clarity / Trust / Control / Calmness がすべて ≥ 6.0
レビュアー      ≥ 3 人（1 人の点を平均と呼ばない）
```

満たして初めて **「高品質な UI である」** と言える。
競合より優れているかは、これとは**別**（`../CLAIMS.md`）。

---

## 採点のしかた

`reviews/<名前>.yaml` を置く。雛形は `reviews/_template.yaml`。

```sh
bash scripts/qualitative-gate.sh
```

レビュアーが 0 人なら `UNSCORED` を返す。**0 人を「合格」にしない。**
