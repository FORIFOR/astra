# 設計 8 項目の採点票（ブランド名を伏せて）

画像 A / B / C を、**製品名を伏せ、順序を入れ替えて 10 回**見せる。
毎回この 8 項目だけを順位付けする。点数ではなく順位にするのは、
7 段階の絶対点がこの採点者では安定しなかったため（`TRUST_SPLIT.md`）。

| # | 項目 | 問い |
| --- | --- | --- |
| 1 | information hierarchy | 3 秒見て、最も重要な情報を言えるのはどれか |
| 2 | surface density | 詰まりすぎず、空きすぎていないのはどれか |
| 3 | visual craft | 間隔・字面・揃えに粗さが無いのはどれか |
| 4 | state legibility | いま何が起きているかが読めるのはどれか |
| 5 | control visibility | 止める・戻す手段が見えているのはどれか |
| 6 | provenance visibility | 出てきた情報の出どころが見えるのはどれか |
| 7 | screen occupation | 画面を占領していないのはどれか |
| 8 | feature/state coverage | どの状態を持っているかが絵から分かるのはどれか |

## 出す形

```json
{"round": 1, "order": ["B","A","C"],
 "ranking": {"information_hierarchy": ["B","A","C"], "...": []},
 "visible_evidence": {"A": ["絵から読めた文字や要素"], "B": [], "C": []}}
```

`visible_evidence` は照合に使う。絵に無いものを根拠にした回は無効。

## 勝率の出し方

```
Astra が 1 位になった回 / 10   >= 70% を目標
```

**8 項目すべてで勝つ必要は無い。** どこで勝ちどこで負けたかを出す。

## この採点で言ってよいこと

```
✅ 「公開素材で見るかぎり、この項目は Astra のほうが良い／悪い」
❌ 「Astra のほうが使いやすい」      操作していない
❌ 「Astra のほうが速い」            測っていない
❌ 「Astra のほうが優れている」      これだけでは足りない
```
