## 1. Context Engine（§6）

### 1.1 Capsule だけが外へ出る

正本 §6.3「Raw local data を何でも cloud へ送らない」。

決定: **Capsule を作る関数以外に、外向きの経路を持たせない。**
`selected_text` などの生データは、`allowed_raw_attachments` に
明示されたものだけが載る。載せる判断は利用者の操作に紐づく。

### 1.2 機密度は上へ寄せる

Capsule の `sensitivity` は、含まれる source の**最も高いもの**にする。
低いほうに寄せると、REGULATED を含む束が PRIVATE として出ていく。

### 1.3 REGULATED は判定できない限り出さない

`mayLeaveDevice` は既にその形になっている。
plugin policy の規則は未実装（OQ-25）なので、`regulatedAllowed` は
呼び出し側が明示的に渡さない限り false。

## 2. Conversation Engine（§7）

### 2.1 Lane は入力から決まる

正本 §7.4 の Lane（chat / dictate / edit / research / action / meeting /
specialist-agent）は**利用者に見せない**。モードを選ばせないのが
正本 §2 の前提なので、Lane は入力と文脈から決める。

**モデルに決めさせない。**規則で決まる部分を規則にしておかないと、
「なぜこの Lane になったか」を説明できなくなる。
規則で決まらないものだけ chat に落とす。

### 2.2 参照解決

`ConversationState.referents` に、直近で触れたものを順に積む。

- 「それ」「あれ」→ 直近の referent
- 「2番」→ 直近に提示した一覧の 2 番目
- 「昨日の続き」→ 前日の会話 / task

**解決できないものを埋めない**（AC7-5）。
埋めると、別のものに対して動いてしまう。

### 2.3 聞き返さない

正本 §7.2「no repeat questions when context exists」。
必要な項目が文脈から埋まるなら聞かない。埋まらないものだけ聞く。

### 2.4 barge-in と打ち切り

新しい入力が来たら、走っている応答を打ち切る（正本 §7.2）。
**途中まで出した文字は残す。**消すと、何が起きたか分からなくなる。

### 2.5 圧縮

会話が伸びたら、直近 N turn 以外を要約に畳む（正本 §7.2）。
要約は**捨てるのではなく畳む**ので、畳んだ事実は残す。
