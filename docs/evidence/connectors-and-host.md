# 端末で動かす — 受け入れの記録

正本 §2.4・§4.4・§9・§16.1・§21、UI/UX §22。2026-08-27。

## なぜ端末なのか

connector の資格情報も、利用者が持ち込んだモデルの利用権も、**端末の
資格情報ストアにしかない**。cloud はトークンを持たないので、Gmail も
Calendar も呼べない。呼べないものを呼べるふりで実装すると、いずれ
「サーバにも置けば簡単になる」に負ける。だから道を作らない。

cloud は「これをやってほしい」を置き、端末が取りに来て、端末で走らせ、
**結果だけ**が戻る。トークンは受け渡しの表を一度も通らない。

## 故障注入

| 起こしたこと                          | どう答えたか                                            |
| ------------------------------------- | ------------------------------------------------------- |
| 403（API 未有効）                     | `permission_denied`                                     |
| 403（scope 不足）                     | `insufficient_scope` — **別物として扱う。直し方が違う** |
| 403 で一覧を引く                      | 例外。**空の一覧にしない**（「メールが 0 通」に見える） |
| 429（Gmail / 検索 / 画像 / 読み上げ） | すべて `rate_limited`                                   |
| 通信断                                | `timed_out`。**「見つからなかった」にしない**           |
| 壊れた応答（HTML）                    | 例外。空の成功にしない                                  |
| 壊れた応答（画像）                    | `provider_error`。空の画像を作らない                    |
| 壊れた応答（モデル）                  | `llm.unreadable_output`。散文を答えにしない             |
| 401（取り消し済み）                   | `token_expired` →「つなぎ直してください」               |
| 応答が返らない                        | 制限時間で打ち切り                                      |
| 端末が同じ結果を二度返す              | 2 度目を拒否。**古い結果で上書きさせない**              |
| モデルが途中で使えなくなる            | `not_signed_in` / `rate_limited` / `crashed` を区別     |
