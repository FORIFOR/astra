# 調べる — 実測の記録

正本 §8、UI/UX §15。測ったのは 2026-08-27、この端末（claude 2.1.246）。

## 何を通したか

問い →（端末で web 検索）→ 出典 →（端末で主張の抽出）→ 根拠の検査 →
（端末で統合）→ 結論と、その結論が立っている根拠、まで通した。

問い: 「東京エレクトロンの2025年3月期の売上高は？」

| 段                             | 時間  | 結果                                           |
| ------------------------------ | ----- | ---------------------------------------------- |
| `search.web`                   | 16.1s | 出典 4 件。**すべて実在の URL**                |
| `llm.extract_claims`（1 件目） | 5.3s  | 主張 3 件を採用                                |
| `llm.extract_claims`（2 件目） | 3.9s  | **0 件。**抜粋が題名だけで、根拠にならなかった |
| `llm.synthesize`               | 4.3s  | 結論 2 件。どちらも根拠つき                    |

出来上がった結論:

```
- 東京エレクトロンの2025年3月期の売上高は2兆4,316億円である
    supports: [0] -> 東京エレクトロンの2025年3月期の売上高は2兆4,316億円である
- 2025年3月期の売上高は前年比32.8%増加した
    supports: [1] -> 2025年3月期の売上高は前年比で32.8%増加した
```

数字は同社の開示（2兆4,315億68百万円、前期比32.8%増）と一致した。

**2 件目の出典から 0 件しか採らなかったのが、この仕組みの要**。
その頁の抜粋は題名の繰り返しで、主張を裏づける文字列が無かった。
「もっともらしい主張」を作れば 3 件は採れたが、**原文に無い根拠は捨てる**。

## 実接続で見つけた取り違え

web を引かせると、Claude Code は答えのあとに
`Sources: [example.com](https://…)` を足す。CLI の親切で、消せない。
返事全体を JSON として読んでいたので、**正しく引けた検索結果ごと捨てていた**
（`llm.unreadable_output`）。先頭の JSON だけを切り出すようにした。
散文しか無い返事は、いまも捨てる。

## どの検索を使うか

既定は端末。`ASTRA_SEARCH_PROVIDER` で Brave / Tavily / Google を選べる。
**既定を第三者に置かない**のは、調べたい内容そのものが問い合わせ先へ渡るから。

| 提供者                           | 状態                                               |
| -------------------------------- | -------------------------------------------------- |
| 端末（Claude Code の WebSearch） | **実測済み**（上記）                               |
| Brave Search API                 | 実装済み・**未検証**（鍵が無い）                   |
| Tavily                           | 実装済み・**未検証**（鍵が無い）                   |
| Google Programmable Search       | 実装済み・**未検証**（鍵と検索エンジン ID が無い） |

3 つは単体試験で形と失敗の扱いを押さえてあるが、**実際の応答では確かめていない**。
