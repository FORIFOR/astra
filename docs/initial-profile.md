# 初回の Astra Profile

Google / Microsoft の最初の読取接続後に、Home の同じ領域で「接続 → 解析中 → 結果確認」を表示する。結果は現在の仕事、よく関わる人、直近の優先事項、仕事の傾向、未完了の項目の5つに絞る。確認後は Home に戻り、この初回プロファイルを自動で作り直さない。

## 読取範囲と表示

- 最初に接続したプロバイダーの、許可済みの読取接続だけを使う。送信用トークンは使わない。
- カレンダーは過去90日から今後45日。メールは直近45日、受信・送信それぞれ最大50件。
- メールの件名・差出人・宛先・スレッド等を使用し、本文と抜粋は初回解析データに含めない。連絡先はメールの相手の出現頻度から整理する。
- 件数は読取が完了した実件数。途中の発見数も保存済みデータから算出し、例示の数字や進捗率で補わない。
- 推定は既存の仕事グラフの規則を使う。情報不足は空欄の説明で示し、プロジェクトや未完了項目を捏造しない。
- 15〜30秒は目標で、待ち時間を演出しない。Google の1回の実測では解析開始から結果準備まで約2.3秒。15〜30秒を保証する値ではない。

未接続・未許可のソースはその旨を表示する。一部を読めた場合は不足を示して結果確認へ進む。全ソース失敗時は再試行できる。確認前は回答向けのプロファイルとして採用せず、Looks right または編集後の保存で5項目を確定する。

## 保存・再開

`initial_profiles` に tenant / user ごとに1件を保存する。開始は冪等で、再接続・アプリ再起動でも同じ状態を読む。AgentHost はジョブの有無を確認し、5分の排他的なリースで初回読取を実行する。停止した worker のリースは失効後に引き継げる。確認済みジョブは再実行しない。既存の通常データ同期とは別で、継続的なプロファイル再解析や新しい Memory 画面は追加しない。

初回解析のメタデータは専用の `artifact_snapshot` に一時保存し、通常同期の本文・推定情報・同期カーソルを上書きしない。リース引継ぎ時は古い進捗とスナップショットを消し、ユーザー確認後はスナップショットを破棄して確定した5項目を残す。

実行には、新しい DB マイグレーションを適用した gateway と、同じユーザーに認証された AgentHost が必要。macOS の既存開発用サインインは再起動時のユーザーIDを維持するよう修正した。今回、新しい本番ユーザー登録・認証基盤は追加していない。

## 検証

DB / API テストで一度だけの開始、排他実行、tenant 分離、途中の実データ集計、失敗と再試行、ユーザー編集、確認後の固定を検証する。AgentHost テストでは期間・件数上限、プロバイダー分離、抜粋除去を確認する。

`AstraMac --selftest initialprofile <output-directory>` は、解析中・結果確認・編集を明暗両テーマで描画し、実際の編集ボタンを操作する。`docs/golden-screenshots/initial-profile/` の画像・geometry はこのテストの架空データであり、ユーザーの実アカウントの分析結果ではない。

Google の読取専用実サービス検証では、メール51件・予定7件の解析、結果確定、同じプロファイルの再取得、再読取なし、Home API取得まで成功した。`scripts/reality/run-initial-profile-live.sh` で再現できる（事前の読取認証設定が必要）。Microsoft とネイティブ画面の通し操作は引き続き未検証。
