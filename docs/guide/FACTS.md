# ガイドの「事実」の棚卸し（調査ターン、2026-09-03）

`docs/guide/build.py` が手で写している UI の語を、**実アプリのどこで定義されているか**まで
辿った表。目的は、UI が変わったのに説明書だけ古い（0.1.1 の「音声入力 … 長押し」）を
機械で止める仕組み `UserFacingFacts` → `--selftest facts` → `fact("key")` → `verify-guide-facts.sh`
の入力を決めること。**この文書は調査のみ。コードはまだ寄せていない。**

対象は 4 分類だけ（操作ラベル / ナビ・見出し / Permission 名 / Shortcut）。本文の説明（prose）は対象外。

行番号は commit 4d6d712 時点。`guide` 列は `docs/guide/build.py` の行。
`要否` の記号: **要** = 共有定数にして fact で参照する / **済** = 既に enum 等の単一定義があり、facts はそれを読むだけ /
**書式** = N を含む書式なので fact にせず prose 扱い / **UI のみ** = ガイドに出ない（facts に入れるが参照は無い） /
**外** = 対象外。

**UI だけにある語**（ガイドに無い、facts には入れるが参照なし）

**Shortcut が別々に定義されている**

- ⌘↩ / esc: `.keyboardShortcut(...)` と `KeyBadge("…")` が独立（鍵を変えても表示が変わらない）。
- ⌘O / ⌘, / ⌘Q: `keyEquivalent` が唯一の定義で、ガイド図はそこから生成済み。

## 6. 実装ターンへの申し送り

- 文字列は全て literal で `NSLocalizedString` / `String(localized:)` は使っていない（Sources 内 0 件）。
  `--selftest facts` の locale 固定（ja-JP）は現状は形式上だが、将来 en を足したときに崩れない形で入れる。
  `GlobalShortcut.label()` は keyCode から組むので言語・設定非依存。
- `confirmation.send` の正本は「demo の確認」。SelfTest の 4 箇所の literal も `UserFacingFacts` を参照させ、
  golden 07-confirmation とガイド本文が同じ値を持つようにする。本文は「例: 送る」と読めるようにする（prose の修正 1 行）。
- `recording.hero` は Swift の fact と Rust の `hero_text` を selftest で突き合わせる（値の重複定義は残るが不一致は FAIL）。
- `permission.screenRecording` は「画面収録」に寄せる（Settings と OS の名前が同じ。DS-06 の用語統一で、造形ではない）。
  `PermissionCenter.Kind.label` はそこから引く。
- 保護語（build.py に literal で書いたら FAIL）の初期集合: 上表の **要** の表示文字列すべて + `録音の開始 / 停止`（乖離を再発させない）。
- ガイド本文の L106 の「の」は実装ターンで `fact("settings.shortcutRow")` に置き換わり自然に直る（UI は触らない）。
- UI 側の変更は「literal を定数参照へ置き換える」だけで、表示文字列は変えない（画面収録の統一を除く）。Craft Freeze の対象外。
